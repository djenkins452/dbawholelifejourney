## 1. What WLJ is

**Whole Life Journey (WLJ)** is a Django personal operating system — a **Personal Truth Platform** — with an **AI Chief of Staff** as its primary surface. It holds the deterministic truth of a person's whole life across domains: health, medical, meals, faith, journal, capture/notes, relationships, purpose/goals, finance, life/tasks/calendar, brain training, and more.

The user chooses a **default relationship** with their AI (Chief of Staff, Best Friend, Coach…) and a **display name** for it (Clara, Beth, Jarvis, Friday…). Those are preferences. The system is always the **WLJ Chief of Staff**.

## 2. Why it exists (product vision)

`docs/WLJ_PRODUCT_VISION.md` is the highest-level "why." In one line:

> **WLJ owns the deterministic truth of a person's life; the conversational model reasons over it.** "The model reasons. WLJ knows."

The point of the product is **trust**. The only success metric is: *if this were the only conversation a paying customer ever had with their Chief of Staff, would they immediately want to use it again tomorrow?* Elegant architecture is never the product — the customer experiences trust, not layers.

A core engineering consequence: **simplicity**. Before building anything, ask "can the conversational model already do this well?" If yes, don't build it — improve the *truth* available instead. As frontier models improve, **WLJ gets simpler, not more complex.**

## 3. Why the OpenAI pivot happened (the defining decision)

WLJ originally tried to build **reasoning inside WLJ** — a "Conductor" with conversation lanes, a classifier, composition passes, and an in-process assistant (historically nicknamed "Beth"). That approach produced a specific, repeating failure: WLJ assembling a sentence from independent fragments contradicted itself (the canonical example: *"6:15 AM tonight,"* stitched from two independent time sources). The contradiction was **structural**, not a bug to patch.

On **2026-07-09** the architecture pivoted: **WLJ stopped reasoning.** A provider-agnostic conversational model (**currently OpenAI**, behind one Model Interface seam) now **drives the turn and owns all reasoning**; WLJ owns deterministic truth, calculations, validation, actions, and audit, and hands the model **composed briefings** (facts with a freshness/confidence/source envelope), never raw signals and never a reasoning engine to imitate.

This is why the governing rule is: **do NOT build a reasoning engine inside WLJ.** A reasoning miss is fixed with better truth delivery, better context, a truth/action tool, or a corrected AI Relationship — never a bespoke WLJ "mind." The retired reasoning-engine docs are preserved and bannered HISTORICAL (see the documentation inventory).

## 4. Current architecture (the shape today)

Four layers, diagnosed **top-down**; fix the first that failed:

1. **Truth (WLJ)** — deterministic facts, calculations, history, preferences. One authority per domain. Most fixes live here.
2. **Reasoning (the model)** — OpenAI drives the turn, reasons over the briefings and tools WLJ provides.
3. **Action (WLJ)** — the safe deterministic path: validate → confirm → execute → audit + provenance.
4. **Experience** — the pages, Current Context, and conversation the customer actually feels.

Load-bearing pillars:
- **Current Context** — every page declares what the user is looking at (detail→object; overview→deterministic summary), resolved server-side; the model answers from it before retrieving. Related truth may *enrich* it but never *replace* it.
- **Execution Truth / Execution Decision Authority** — one deterministic producer of execution truth. It owns the buckets **current action · completed today · overdue · due now · coming up · later**; every surface consumes it, none re-derives. Recurring execution is **occurrence-based**: "today's execution" (the occurrence due today) and "history" (what happened previously) are **separate deterministic truths** and are never blended.
- **Mission Link** — action→mission connection as deterministic relationship facts (WLJ computes it; the model reasons *from* it). Production-complete.
- **Multimodal** — perception is the model's; the deterministic spine is WLJ's. Pattern: **the model perceives → WLJ validates truth → WLJ executes the action → the model communicates the real results.** Production-complete (see maturity).
- **Model Interface + Executive Context Envelope** — the single seam and the structured per-turn context (AI Relationship + Current Context + deterministic understanding) handed to the model.
- **Conversation integrity** — the transcript stays a faithful record of what the user actually submitted; artifacts derived from an upload become deterministic truth with provenance, but the transcript still preserves the original submission.
- **Reflection** — sits *above* the four layers and only observes; learning is default-deny and never learns around a deterministic defect.
- **Truth Surfaces** — the CoS reasons from **several complementary deterministic truth surfaces**, not `DomainTruth` alone: **Current Context · Standing Context · Personal Truth · DomainTruth · Domain Entity Surfaces · Executive Briefings · Decision Authority.** Each supplies a truth type (summary/detailed/execution/contextual/historical); they are complementary views of one life, not rivals. **A missing `DomainTruth` provider does not make an answer impossible** — the fact may legitimately arrive via another surface (Goals answered from Standing Context; Fitness from a Domain Entity Surface). Validated by production certification, 2026-07-18. Full catalog: `docs/WLJ_TRUTH_SURFACES.md`.

Stack: Django 4.2.27 (note: CLAUDE.md says "5.x"; runtime is 4.2), PostgreSQL/Redis, Celery worker+beat, Gunicorn, Railway (Nixpacks), OpenAI. iOS SwiftUI wrapper. ~4,400 tests. Soft deletes, not hard deletes.

## 6. Major lessons learned

- **Don't assemble sentences from independent fragments** — it manufactured contradictions. One author (the model), one composed truth. This lesson *caused the pivot*.
- **Eliminate the class, don't detect the symptom.** We didn't "fix" *"6:15 AM tonight"* — we removed the condition that let one sentence draw from two time sources.
- **Occurrence-scoped truth.** "Completed today" must mean *the occurrence due today is done*, not *a timestamp landed today* — a recurring prior occurrence completed after midnight is history, not today (the "Check on Von's House" incident).
- **Prove the runtime path before editing.** A passing unit test is not proof; trace Browser→…→Composer→DB and find ALL producers (persisted ≠ live).
- **Request-path safety.** Never compute heavy analytics or call the LLM inline on a request; read snapshots or return "pending." Live fallbacks caused production timeouts.
- **Improve truth before adding intelligence.** Most "make the assistant smarter" asks are really "give the model better truth."
- **Certification drives the roadmap, not intuition** (proven 2026-07-18). Two-owner model — Deterministic (Owner-1) → Customer Truth (Owner-2) → Executive Judgment — with per-question structured evidence and first-failing-layer attribution. Rank work by *measured* customer impact; untested = **NOT YET MEASURED**, never "low priority." The loop and instrument are in `03_ENGINEERING_OPERATING_GUIDE §3c`.
- **A missing provider is not a missing answer.** *"A missing provider changes which deterministic truth surface supplied the answer; it does not necessarily determine whether the answer is possible."* Trace which surface served an answer before concluding a gap exists (`docs/WLJ_TRUTH_SURFACES.md`).
- **Validate at the altitude you're certifying.** *(The defining lesson of the Truth Validation Center build, 2026-07-19.)* The Truth Validation Center certifies **implementation** — it separates Truth Layer · Object Resolution · Provider · Routing · Tool Selection · Answer Grounding, which is *invaluable for engineering* (it turns "the CoS got it wrong" into "which layer failed"). But that is the **wrong altitude for operator certification of the Chief of Staff.** Field- and layer-level validation proves the parts work; it does **not** prove the *conversational experience* is one a paying customer would trust. **Operator certification must validate natural conversation** — "does my Chief of Staff behave like a knowledgeable Chief of Staff?" — in the user's own language, never database or developer terms. Keep both instruments, and use each at its altitude: the layer-level Center for engineering diagnosis, natural-conversation testing for operator certification. (This is not a failure of the Center — it is the right tool at the wrong level for that job.)
- **WLJ records what happened; it never interprets what happened between the user and God.** *(Faith First Light, 2026-07-20.)* A Faith surface states **deterministic truth only** — it says *"You completed today's reading,"* never *"You sat with Him today"*; it renders a reading, a prayer, a streak, or a milestone as the fact it is, never a verdict on the user's spiritual state or God's action. This is the domain expression of the platform rule (WLJ owns truth; the model interprets; WLJ never renders a verdict) — the same class as "never fabricate a fact." The conversational model may reflect on what a fact might mean; the WLJ surface may not.
- **Conversation State is the deterministic working-state authority — and it eliminates systems, it never becomes one.** *(Conversation State Management, foundational capability shipped + frozen 2026-07-20.)* **Current Context** answers *"what PAGE is the user on?"*; **Conversation State** answers *"what are we talking about / doing / waiting on?"* — a different deterministic truth, carried **inside the Executive Context Envelope** (a peer field to Current Context; **not** a new retrieval surface / tool). One conversation-scoped authority (`apps/ai/model_interface/conversation_state.py`, `AssistantConversation.metadata["conversation_state"]`); a **compact deterministic index** — identifiers, lifecycle scalars, timestamps, refs to durable truth — that must **never** hold summaries, transcripts, model prose, inferred intent, or reflection (the model reasons OVER it; it never writes it — writer- and schema-contract tests enforce both). Lifecycle is **event-driven-primary** (supersession/resolution/explicit-clear); turn/time are last-resort fallbacks for the *semantic* abandonment WLJ cannot observe (that is the model's job, I.2). Two corollaries proven in production: (1) **preserving an artifact *reference* ≠ keeping it *perceivable*** — an active image/video must be RE-DELIVERED (re-perceived) on follow-ups, and Conversation State owns *which* artifact is active while **adapters** reconstruct *how* it becomes perceivable (it is never an artifact-processing engine); (2) before extending it, run the **Expansion Test** (`03 §3f`) — if it does not replace a deterministic system AND eliminate duplicate logic, it is scope creep. Governing doc: `docs/WLJ_CONVERSATION_STATE_ARCHITECTURE.md`.
- **One Chief of Staff, many workspaces — the product is NOT "AI added to each page."** *(Strategic realization, 2026-07-20; the governing mental model for all future domain work.)* WLJ is **one Chief of Staff that understands every domain** — not Journal-AI + Health-AI + Travel-AI. The **relationship never changes; only the workspace changes.** Pages are **workspaces** (Journal, Health, Travel, Legacy, Faith, Capture…), not separate AI experiences; the CoS is the constant companion helping the user work within whichever workspace serves the current intent. The invariant loop: **One CoS → Current Context → current workspace → relevant truth → relevant tools → the conversation continues.** This **elevates Current Context from a mechanism to a defining product capability**: the CoS always knows where the user is, what workspace is open, what deterministic truth is already on the screen, which tools are available, and what task the user appears to be doing — and Current Context must **improve** the conversation, never **trap** it (the page can *become part of the answer* — "let's look at it together" — never be replaced). **Navigation becomes a CoS decision**: answer directly when the current workspace suffices; navigate when another workspace's surface *is* the best answer ("show me my weight history" → the graph) or the intent requires it ("I'd like to journal" → open the Journal workspace). The conversation never ends; only Current Context changes; the user never feels they changed assistants. This is a **reframing/unification of existing pillars** (single-brain CoS · Current Context · Model Interface) — **NOT new architecture and NOT a Constitutional change**: it forbids exactly what the Constitution already forbids (multiple assistants, duplicate conversation systems, domain-specific AI engines). **Journal is the first fully-realized workspace and the reference implementation** — its Draft→Finish&Review→**Save Journal** lifecycle, Write Together / Talk It Through, Conversation Playbook, Memory Model, Truth Discovery, Review, and Legacy **Publish** are **CoS capabilities**, not Journal-only features. Vocabulary is fixed: the **Journal is Saved; Legacy is Published** — never overload "Publish" for the Journal itself. Generalize by **composition, reuse-first — investigate before coding, never duplicate.**
- **A new domain is designed as a platform *consumer* (a showcase), never a parallel architecture — Travel is the first, designed-not-built.** *(Strategic direction, 2026-07-21; the governing pattern for ALL future domain development, and the direct corollary of "One Chief of Staff, many workspaces" above.)* A future WLJ domain is **not "a module with AI added to it."** It is a flagship domain **built on top of the evolving CoS platform**, exposing exactly four platform-shaped things — **deterministic truth · workspaces · actions/tools · Current Context** — over which the **one** Chief of Staff reasons. It introduces **no** domain AI, conversation engine, domain-specific reasoning, second assistant, or duplicate memory/conversation system (all already forbidden). It **consumes, never reimplements**, the reusable platform capabilities being generalized out of Journal: **Current Context · conversation continuity · workspace navigation · the discovery framework · the draft/workflow framework · the confirmation framework · multimodal intake · truth extraction · shared action execution.** The success test is that the customer *never feels they changed assistants* moving between domains. **Travel Intelligence is the worked example** — designed this session (`docs/WLJ_TRAVEL_INTELLIGENCE_ARCHITECTURE.md`, DRAFT), a lifelong domain owning deterministic travel truth (trips, drafts, destinations, routes, reservations, packing, travel sessions, GPS history, arrival/departure, mileage, maintenance, expenses, photos, memories, trip stories, preferences) and exposing **many workspaces** (Travel Home · Active Trip · Planning · Route · People · Packing · Reservations · Budget · Live Trip · Trip Story · Memories · Map), with Current Context adapting as the user moves between them. Two concepts to carry forward: (1) **Workspace ≠ Session** — a *workspace* exists forever (dream in January, relive in December); a *Travel Session* is a transient capture window active **only while actually traveling** (GPS/stops/fuel/lodging/photos/notes/journal/expenses/weather/health/people/receipts), which becomes permanent trip history on return. (2) **Deterministic location truth is a shared *platform* capability, not a Travel silo** — WLJ becomes *context-aware* ("I see you've arrived at Aunt Janice's," "oil service due soon"), never a navigation product (that's Apple/Google/Garmin); multiple domains consume it, and **Travel is its first major consumer, not its owner.** **Sequencing:** Travel is **NOT** the next implementation milestone — the platform evolution (the workspace/Current-Context/reusable-conversation work, Journal as reference) comes first; Travel is designed now so the platform is shaped with a second real consumer in mind. In-Constitution (no Review): it forbids exactly what the Constitution forbids.
- **The source is never the feature — the structured candidate is.** *(Measurement Session Capture, production-validated 2026-07-19.)* We nearly built a "Renpho integration" (reverse-engineering, then Terra — both dead ends: Terra's model has zero circumference fields). The real capability is **Measurement Session Capture**: ANY source — screenshot, photo, typed text, voice, PDF, CSV, API, BLE — produces the SAME *structured candidate*, which flows through the ONE multimodal truth spine (perceive → validate → confirm → persist canonical truth → audit/provenance). **OpenAI perceives; WLJ owns deterministic truth** — validated end-to-end (screenshot → `BodyMeasurementSession`; CoS answered from truth, not the image). Before building a vendor/source integration, ask "can this be a new *arrival* at an existing intent?" Corollary (the Shoulder defect): **normalize source vocabulary to canonical, and NEVER silently drop an unrecognized value** — surface it (skipped list + log). A silent drop is a whole *class* of invisible truth loss; eliminate it, don't patch one label.
