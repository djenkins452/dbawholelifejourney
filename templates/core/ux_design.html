Core Design Philosophy

Whole Life Journey is built on a foundation of calm, respectful design that prioritizes user wellbeing over engagement metrics. Our guiding principles:

🍃

Calm Over Clever

Simple, peaceful design that doesn't overwhelm. No flashy animations or attention-grabbing elements.

🎯

Simple Over Complex

Easy to use, nothing overwhelming. Features reveal progressively as users become comfortable.

🤝

Respect Over Pressure

No gamification, no streaks, no guilt. We don't manipulate users into engagement.

✨

Clarity Over Features

Focused functionality. Every feature serves a clear purpose in the user's wellness journey.

🌱

Reflection Over Performance

Growth, not metrics. We encourage self-awareness without judgment or competition.

🔒

Stewardship Over Control

Your data belongs to you. Full export, deletion rights, and transparent data practices.

User Personas & Design Considerations

We design for diverse users at different stages of their wellness journey:

👶

New User

Characteristics: First-time app users, may feel overwhelmed by features, unsure where to start.

Design Accommodations:

  • 6-step onboarding wizard with progressive disclosure
  • Module selection during setup (only enable what matters)
  • Empty state guidance with helpful prompts
  • "Where to start" suggestions on dashboard
  • Context-aware help icons (?) throughout the app
  • Teaching Tool AI that provides navigation guidance
💪

Experienced User

Characteristics: Regular users who know the app well, want efficiency and depth.

Design Accommodations:

  • Cascading dropdown menus for direct navigation (skip module home pages)
  • Dashboard tile shortcuts for quick logging
  • Keyboard shortcuts (ESC to close menus)
  • Collapsible navigation on mobile (hide on scroll)
  • Collapsible left rail on desktop (icons only mode)
  • Favorites system for quick access to frequent pages
📱

Mobile-Primary User

Characteristics: Primarily uses phone, logs data on-the-go, needs quick entry.

Design Accommodations:

  • Mobile-first responsive design (375px minimum width)
  • 44x44px minimum touch targets
  • 16px font minimum on inputs (prevents iOS auto-zoom)
  • Bottom navigation for thumb-friendly access
  • Native iOS app with HealthKit integration
  • Swipe-friendly list views
✝

Faith-Focused User

Characteristics: Primarily interested in spiritual growth, may not need health/finance features.

Design Accommodations:

  • Faith module can be used standalone (all other modules disabled)
  • "Faith Only" subscription tier for minimal-cost access
  • Christian Faith theme option
  • Prayer tracking with answered prayer celebrations
  • Bible reading plans with difficulty levels (Beginner/Intermediate/Advanced)
  • Daily verse with reflection prompts
❤

Health-Conscious User

Characteristics: Focused on health metrics, may use wearables, wants data insights.

Design Accommodations:

  • 17+ health metrics across vitals, lifestyle, and specialized categories
  • Apple HealthKit integration (23 data types)
  • Dexcom CGM integration for continuous glucose monitoring
  • Comprehensive medicine management with schedules and adherence
  • Nutrition tracking with FatSecret barcode scanning
  • Cycle tracking with predictions (for female users)

Onboarding Experience

Our 6-step onboarding wizard uses progressive disclosure to reduce cognitive load and let users customize their experience from the start.

Step Name Purpose User Benefit
1 Welcome Introduction and value proposition Understand what the app offers
2 Theme Visual theme selection Personalize the look immediately
3 Modules Enable/disable feature areas Only see what's relevant
4 AI AI coaching preferences Choose coaching personality
5 Location Timezone and weather location Time-aware features work correctly
6 Complete Confirmation and dashboard access Ready to start their journey

Why Progressive Disclosure?

By letting users choose their modules upfront, we avoid overwhelming them with features they don't need. A faith-focused user never sees health metrics. A health enthusiast doesn't see prayer tracking. The app adapts to each user's actual needs.

Navigation Design

Desktop Navigation

Desktop users get a full sidebar with cascading dropdown menus that allow direct navigation to any page without visiting module home screens first.

  • Hover to reveal dropdown menus
  • Health uses a "mega menu" with 5 columns for its many features
  • Click outside or press ESC to close all menus
  • Sidebar can be collapsed to icons-only mode

Mobile Navigation

Mobile users get a bottom tab bar optimized for thumb-friendly access:

  • 5 primary tabs in bottom navigation
  • Tap to toggle accordion-style dropdowns
  • "More" menu for overflow items
  • Optional: hide navigation on scroll (setting)

Navigation Help System

The app includes a Teaching Tool with 76+ destination mappings that help users find features through natural language:

Example Teaching Tool Queries

  • "Where do I log my weight?" → Health > Weight
  • "How do I delete my account?" → Settings > Profile > Delete Account
  • "Where are my prayer requests?" → Faith > Prayers
  • "How do I track habits?" → Goals > Habits

Accessibility & Responsive Design

Responsive Breakpoints

Device Breakpoint Layout
Mobile max-width: 480px Single column, bottom navigation, stacked forms
Tablet max-width: 768px Adaptive columns, collapsible sidebar
Desktop min-width: 769px Full sidebar, multi-column layouts

Accessibility Features

  • ARIA support - Full aria-expanded, aria-haspopup attributes on interactive elements
  • Keyboard navigation - ESC closes menus, Tab navigates forms
  • Focus indicators - Visible focus outlines for keyboard users
  • Screen reader compatible - Semantic HTML structure throughout
  • Color contrast - All themes meet WCAG contrast requirements
  • Touch targets - Minimum 44x44px for interactive elements
  • No auto-zoom - 16px font minimum on inputs prevents iOS zoom
